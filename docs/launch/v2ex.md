## 正文

地址：https://app.aiuos.com ｜ 源码（MIT）：https://github.com/401040579/dev-toolbox

起因是排查短信通知和 POS 对接问题时，总要把 webhook 的 payload、Base64 过的订单事件、客户收到的短信文案往各种在线工具里粘，既慢又不放心。于是做了一个自己用的工具箱，原则只有一条：**所有处理都在浏览器里完成，没有后端，不用登录，输入不上传。** 做成了 PWA，联网打开过一次之后离线也能用。

目前 90 个工具、11 个分类，Base64 / JWT / UUID / 时间戳 / 正则 / JSON 格式化这些常见的都有，就不展开了。下面说两个别处不太常见的。

### 1. 短信分段计算器

贴一条短信进去，它告诉你：

- 这条会按 GSM-7 还是 UCS-2 发，要几个分段（160/153 或 70/67 的边界、拼接用的 6 字节 UDH 都算进去了）；
- **到底是哪几个字符**把整条短信逼成了 UCS-2：弯引号「“”」、破折号「—」、全角标点、emoji 会被逐个标出来；
- 还剩几个字符会跨到下一段；
- 开启 Smart Encoding 后，把这些字符替换成 GSM-7 等价字符的效果（字符表来自 Twilio 开源的 message-segment-calculator，MIT，有署名）。

典型场景：运营从 Word 里复制过来一条取餐通知，一个弯引号让一条短信变两条，成本翻倍，没人知道为什么。中文短信本来就是 UCS-2，这个工具对中文的价值主要是看 70/67 的分段边界和 emoji 占位。

边界要说清楚：**结果是估算，不是运营商账单。** 各家网关的编码、拼接头和计费规则不同。

### 2. 二维码传文件

A 设备把文件播成一串动态二维码，B 设备用摄像头对着屏幕扫，两台设备之间不需要任何网络，也没有服务器中转。适合给锁死的 POS 终端、不让插 U 盘的机器、断网的内网机传个配置文件或者日志。

- 用 RaptorQ 喷泉码做纠删：漏扫、乱序的帧靠修复帧补回来，不用从头重播；停掉摄像头再开，未完成的文件接着收。
- 三档：兼容（384 字节 / M 级纠错）、高速（QR V30，默认 4 码并行、30 FPS）、极限（V40，大屏用）。
- 收完先校验长度和 SHA-256 才允许预览或保存；只预览 PNG/JPEG/WebP/GIF/AVIF/BMP，HTML/SVG/视频一律只给下载。
- 限制：单文件 5 MiB，一批 8 个文件 / 10 MiB。摄像头需要 HTTPS 或 localhost，且必须手动点开始。
- 速度：1 MiB 随机文件在**模拟摄像头视频流的 Chromium 测试**里约 3.9 秒传完（约 263 KiB/s）。这是合成环境的数据，**真机手机对着笔记本屏幕的速度我还没系统测过**，受摄像头、屏幕、光线、对焦影响。两端都得用这个页面，系统相机扫不了。

还有一个「二维码传文本」的变体，专门传一段配置、一个公钥指纹之类的短文本。

### 其他

- Pipeline：把多个转换串起来（Base64 → JSON 美化 → SHA-256），本地保存，也能用链接分享一个合成示例。注意分享链接把全部输入放在 URL 片段里，拿到链接的人都能看。
- JSON 结构化 diff、10 MiB 日志分析（Worker 里跑）、智能粘贴（识别 JSON / JWT / 时间戳 / Base64 直接跳对应工具）、草稿跨刷新恢复。
- 中英双语。

### 隐私

默认构建**没有任何统计代码**。仓库里留了一个可选的 GoatCounter 开关（无 Cookie、不加载第三方脚本），如果部署方开启，只会上报页面路径和来源站点的域名，不含查询串、URL 片段和任何输入内容。具体发什么，README 的 Analytics 一节和 `src/lib/analytics.ts` 一个文件写完了，可以自己看。

想听的反馈：二维码传文件在你手头的手机 + 屏幕组合上能不能稳定收完（请带上手机型号和用的档位），以及排查短信 / 接口问题时你还有哪些事得离开浏览器去做。
