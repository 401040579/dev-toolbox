# Security reporting

For a vulnerability, use [GitHub private vulnerability reporting](https://github.com/401040579/dev-toolbox/security/advisories/new). Include a synthetic reproducer, affected version/browser, whether code executes or a request occurs, and preview/export/share steps. Do not attach real private data or credentials. General non-sensitive defects can use [issues](https://github.com/401040579/dev-toolbox/issues).

The maintained release line starts with v1.0.0. The security boundary includes local processing, sanitized Markdown/static SVG previews and exports, CSS resource prevention, and validated Pipeline share configurations. Tools that format or decode arbitrary source text produce text for inspection; their output should only be executed in an appropriate environment after review.
